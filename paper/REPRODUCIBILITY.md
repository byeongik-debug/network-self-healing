# 재현성 검증 절차

## 깨끗한 소프트웨어 환경 재현

정확한 배포 커밋을 새로 내려받은 Linux 작업 사본에서 실행한다. 아래 명령은
미커밋 변경이 있는 작업 사본에서는 실행을 거부하고, 임시 디렉터리에 가상환경을
만든 뒤 `requirements.txt`만 설치한다. 이후 전체 테스트를 수행하고 기존 결과를
교체하지 않는 실행별 증거 파일을 생성한다.

```bash
bash testbed/run_clean_reproduction.sh
```

생성된 `results/reproduction/runs/<UTC 시각>/` 디렉터리를 보관한다. 이 디렉터리에는
커밋 해시, 실제 설치 패키지 목록, JUnit 테스트 보고서와 기계 판독 가능한 요약이
포함된다. 동결된 커밋의 새 작업 사본에서 이 디렉터리를 생성하기 전까지는 로컬
실행이 성공했더라도 논문의 재현성 조건을 충족한 것으로 간주하지 않는다.

## Mininet 재현

Mininet과 Open vSwitch가 설치된 Linux에서 다음을 실행한다.

```bash
sudo -E bash testbed/run_mininet_validation.sh
```

`results/testbed/runs/<UTC 시각>/`을 보관한다. 실행 스크립트가 종료 코드 0을
반환하고 JSON에 복구 결과 51/51 및 피해 결과 51/51 일치가 기록된 경우에만 논문
근거로 인정한다. 단위 테스트 통과만으로는 Mininet 검증 근거가 되지 않는다.

## 배포 점검표

1. 모든 소스, 원고 및 체크포인트 이외의 근거 파일을 커밋한다.
2. 변경 불가능한 배포 커밋을 태그하거나 별도로 기록한다.
3. 해당 커밋을 새로 내려받아 깨끗한 환경 재현을 실행한다.
4. 같은 커밋으로 Linux에서 Mininet 검증을 실행한다.
5. 두 실행 디렉터리를 파일명 변경 없이 배포 자료에 포함한다.
6. 보관된 JSON/CSV에 실제로 존재하는 수치만 원고에 인용한다.
